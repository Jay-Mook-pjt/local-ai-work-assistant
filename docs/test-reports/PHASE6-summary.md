# PHASE 6 통합 테스트 종합 보고서

- 일자: 2026-11-24
- 환경: Mac mini (Apple M5 Pro, 24GB), macOS 27.2.1, Ollama 0.40.17 `qwen3:14b`, MLX Whisper `whisper-large-v3-turbo`
- 경로: 모든 시나리오는 실제 사용 경로(브라우저와 같은 Frontend `:3000` → Backend → Worker)로 실행
- 도구: `backend/tests/integration/e2e.py` (재실행 가능, 아래 "다시 실행하기" 참고)
- 개별 실행 결과: 같은 폴더의 `YYYYMMDD-HHMM-e2e-*.md`

## 1. 테스트 방법

macOS 한국어 TTS(Yuna, 음높이 변경으로 화자 3~4명 흉내)와 분홍 소음으로 **정답이 정해진 회의 음성**을 합성해 처리한 뒤 자동 채점했습니다.

| 시나리오 | 길이 | 내용 | 채점 항목 |
|---|---|---|---|
| short | 2분 17초 | 3개 안건, 확정 1건, 담당·기한 있는 업무 2건, 담당 미정 업무, 미결 2건, "제안→확정" 전환 | STT 유사도, 이름 인식, 결정(타임스탬프 ±20초), 결정이 아닌 것, 업무·담당자·기한, 미결, 참석자 외 담당자(환각), 안건 반영 |
| long | 36분 16초 | 6개 안건, 287문장(일반 발언 사이에 정답 사실 배치), 확정 3건, 업무 3건, 미결·보류 3건 | 위와 동일 (27항목) |
| recovery | — | Worker 강제 종료, Ollama 연결 실패, 음성이 아닌 파일 업로드 | 상태 표시, 재처리, 전사문 보존·재사용, 거부 |
| persistence | — | 전체 서비스 stop/start | 회의·회의록·문서·파일 동일성, SQLite 무결성 |

추가로 **사용자 실제 녹음 1건**(12분 33초, 업무 인터뷰)을 처리했습니다. 개인 녹음이므로 이 문서에는 내용을 싣지 않고 수치만 기록합니다.

## 3. 오류 복구 (9/9)
1. 음성 인식 중 Worker를 `kill -9` → 재시작 시 해당 작업을 "중단됨"으로 실패 처리 → 다시 처리하면 완료.
2. Ollama 연결 불가 → "Ollama에 연결할 수 없습니다 … brew services start ollama" 메시지로 실패, 전사문은 보존 → 복구 후 재처리 시 **음성 인식을 건너뛰고** 분석만 실행해 완료.
3. 음성이 아닌 파일(`.m4a` 확장자) → 415 거부, 저장소에 파일 남지 않음.

## 5. 남은 한계 (사용 시 유의)
- **모델 출력 편차**: 같은 입력도 실행마다 미결 사항 개수·논의 묶음이 달라집니다(긴 회의 미결 3~7개). 핵심 사실(결정·담당자·기한)은 근거 검증으로 안정적이었습니다.
- **화자 분리 없음**: 발언자는 항상 `미확인`, 담당자는 발언 내용("○○님이 …")으로만 판단합니다.
- **STT 고유명사**: 사람 이름·업무 용어가 틀릴 수 있습니다. 참석자 입력과 용어집으로 상당 부분 보정되지만, 전사문에서 만들어진 무의미한 단어(예: "채김")가 담당자에 섞일 수 있습니다.
- **수치 누락**: 건수·소요 시간 같은 수치가 요약에서 빠지는 경우가 있습니다(실제 녹음).
- **실제 SMTP 발송 미검증**: 로컬 SMTP 서버로만 확인(PHASE 5). 사용할 메일 계정 설정 후 확인 필요.
- 최종 회의록은 **검토가 필요한 항목**을 확인하고 편집한 뒤 배포하는 것을 전제로 합니다.

## 6. 다시 실행하기
```bash
cd backend
.venv/bin/python -m tests.integration.e2e run short        # 약 1분
.venv/bin/python -m tests.integration.e2e run long         # 약 7분 (합성 2분 + 처리 5분)
.venv/bin/python -m tests.integration.e2e recovery         # 약 3분, Worker를 재시작함
.venv/bin/python -m tests.integration.e2e persistence      # 모든 서비스를 재시작함
```
옵션: `--model exaone3.5:7.8b`(모델 비교), `--keep`(결과 회의를 앱에 남김). 실행 중에는 다른 분석 작업을 넣지 않는 것이 좋습니다(recovery는 Worker를 강제 종료합니다).
